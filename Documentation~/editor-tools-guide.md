# SDK 验证与本地区域地块编辑器 · 操作说明

> 适用版本：MyVerse XR SDK **3.3.0+**（环境化 + 地块防篡改封签）。本文面向接入方，讲两个 Editor 工具的完整操作流程：
> **SDK 验证面板**（环境选择 + 凭据验证，远端能力的前置门禁）与**本地区域地块编辑器**（制作区域对齐用的地块数据）。
> 设计与运行时原理见开发指南 §6.2 / §12。3.1.x～3.2.x 的旧版操作见文末 §6 迁移说明。

---

## 1. 核心概念：环境

SDK 的开发者平台能力按**环境**隔离，在验证面板顶部切换（默认**正式环境**）：

| 环境 | 平台地址 | 验证 | 地块保存 |
|------|----------|------|----------|
| 正式环境 | `http://developer-platform.myverse.fans`（内置只读） | 需要 | 上传成功才落盘 + 自动封签 |
| 测试环境 | `http://172.0.0.218:3888`（内置只读） | 需要 | 上传成功才落盘 + 自动封签 |
| 离线环境 | 无 | 无 | 本地直存（不上传、无封签） |

- **地址内置不可填**——防止手滑连错环境；临时联调特殊地址走设置资产的 `serverUrlOverride` 字段（应急用）。
- **凭据按环境独立**：正式/测试平台的账号体系互相独立，AppId/AccessToken 与验证状态各存一份，切环境后需分别验证。
- **地块数据按环境分组**：每个环境有自己的一组地块条目；地块编辑器只操作当前环境的组。
- 切换环境会同步写入地块数据资产的"激活环境"标记——**运行时按这个标记取对应环境的地块组**（构建期快照，运行时不感知所连中控属于哪个环境）。
- **出包保护**：出包时 SDK 自动校验——激活环境非正式、或激活组封签无效会弹窗确认（可取消出包，防止调试后忘切回环境）；CI/批处理模式只告警不阻塞。

### 前置准备：开发者平台

1. **在目标环境的开发者平台创建游戏**——创建完成后平台生成本游戏的 **AppId** 与 **AccessToken**。
2. **AccessToken 特性**：长期有效；**一个开发者同一时刻只有一枚有效令牌**——平台重新生成后旧令牌**立即失效**；团队共用同一枚（见 §2.4），有人重新生成后全员需更新并重新验证。

## 2. SDK 验证面板

### 2.1 打开方式

- **自动弹出**：导入 SDK 或打开工程时，若**当前环境**尚未验证会自动弹出（每个编辑器会话最多提示一次；离线环境不弹）；
- **手动打开**：菜单 **MyVerse → XRSDK → SDK 验证**。

### 2.2 环境选择与验证

1. 顶部**环境**下拉选择目标环境——服务地址随之只读显示；
2. 填写该环境的 **AppId** 与 **AccessToken**（密码态显示），点**验证**；按钮显示"验证中…"期间请勿关闭窗口；
3. **通过**：弹"验证通过"，该环境凭据落盘（见 §2.4）；**失败**：面板红色提示原因，对照 §2.3 处理。

切到**离线环境**时面板隐藏凭据区，仅提示离线行为（无验证、地块仅本地保存）。

### 2.3 失败原因对照

| 提示 | 原因与处理 |
|------|-----------|
| appId 与 AccessToken 不能为空 | 两项都必填 |
| AccessToken 无效（签名/格式错误或非 API 令牌） | 令牌复制不完整/贴错了别的令牌，回平台重新复制 |
| AccessToken 已过期 | 到开发者平台重新生成 |
| AccessToken 已被重新生成或作废 | 有人在平台重新生成过令牌，向队友要最新的一枚 |
| 网络请求失败：… | 平台服务未启动 / 网络不通 / 环境选错（内网测试环境在外网不可达） |

### 2.4 凭据存储与团队共享

验证通过后凭据写入 **`Assets/MVXRSDK/MVXRSDKSettings.asset`**（不存在会自动创建）：

- 该资产**随项目入 git**——团队共享凭据，一人验证全员生效（每个环境各一份）；
- 刻意**不放 Resources/**，凭据只供编辑器工具链使用，不会打进真机包；
- 重新验证会覆盖该环境已保存的凭据（面板会回填当前环境的值便于查看/更新）。

### 2.5 重新封签

当前环境的地块组**无有效封签**时（旧版迁移数据、或资产被绕过工具手改），面板下方会出现警告与**"重新封签（逐条上传）"**按钮：

- 需当前环境已验证；点击后逐条把该组地块重新上传平台，**全部成功**才写回签名；
- 任一条失败会中断并提示（签名不写入，可重试）；
- 签名写回后运行时恢复使用该组数据（封签机制见 §3.8）。

## 3. 本地区域地块编辑器

### 3.1 用途

制作"本地区域数据列表"资产（按环境分组的地块条目：id / 长 / 宽 / 位置 / 旋转）。运行时 SDK 用中控下发的区域长宽生成临时 id 匹配**激活环境组**的地块条目，按区域公式驱动场景根节点——**地块就是"远端区域在本场景里的摆放标定"**。

### 3.2 创建编辑器对象

Hierarchy 右键 → **MyVerse → 生成本地区域地块编辑器**。

- 生成的对象 tag=EditorOnly，打包自动剔除，不影响真机；
- 工程里已有区域配置文件时会自动挂到"当前配置文件"槽位。

### 3.3 配置文件（数据资产）

- Inspector 顶部"当前配置文件"槽位：指定已有资产，或点**新建**自动创建到契约路径；
- **契约路径**：任一 Resources 根下的 `MVXRSDK/LocalRegionData.asset`（如 `Assets/Resources/MVXRSDK/LocalRegionData.asset`）——运行时按固定路径加载，放错位置工具会给警告、运行时加载不到；
- **请勿在 Project 里直接改这个资产**——它的 Inspector 已只读化；绕过编辑器手改会使封签失效、运行时整组拒用（见 §3.8）。

### 3.4 环境徽标

Inspector 顶部显示**当前环境徽标**（绿=正式 / 橙=测试 / 灰=离线）。列表、新建、保存、删除**全部作用于当前环境的地块组**；切环境（在验证面板）后这里的列表随之切换,编辑中的条目自动退出编辑态。

### 3.5 创建条目

**正式/测试环境**：

1. 点**创建新条目**（当前环境未验证会被拦截并引导打开验证面板；拉取期间按钮显示"拉取中…"）；
2. 弹出**远端规格列表**菜单——条目 id 只能从这里选（id 即远端 tagId，`宽x长` 小写格式，如 `4x6`）：
   - 当前环境已有的 id **置灰不可选**（含未保存的新建草稿）；
   - 远端列表为空会弹提示（确认平台已为该 AppId 配置区域规格）；
3. 选中后进入编辑态，长宽默认取远端下发的尺寸，位置/旋转为零。

**离线环境**：点**创建新条目**直接进入编辑态，**id 手动填写**（格式同远端 tagId：`宽x长` 小写，如 `6x12`；保存时校验非空且组内唯一）。

### 3.6 编辑

**编辑区域**（列表下方独立区块，标题区分"新建条目/编辑条目"）：

| 字段 | 含义 |
|------|------|
| ID | 仅离线环境新建时可填；其余场景 id 不可改（运行时匹配键） |
| 长（米，本地Z轴） | 地块 Z 向尺寸 |
| 宽（米，本地X轴） | 地块 X 向尺寸 |
| 位置 | 地块中心在场景中的位置 |
| 旋转（欧拉角） | 地块朝向 |

- **SceneView 可视化编辑**：编辑中的地块显示蓝色半透明底框 + 位移/旋转手柄，直接拖拽调整；
- **常显选中地块**开关（Inspector 顶部，默认开）：不选中编辑器对象时，编辑中的地块也以橙色描边 + id 标签常显在 Scene 里（受 Scene 视图右上角 Gizmos 总开关控制）；
- 有未保存修改时切换条目/取消会弹确认提示。

**摆放建议**：区域对齐是**世界层级刚体变换**。地块 `position` 参与对齐时是**世界层级直接相减**（与区域 A 同级，不被区域旋转带动）；地块 `rotation` **不参与根节点对齐**（只影响地块可视物显示朝向）。根节点朝向由远端区域 rotation + gameOffsetRotation 决定。

### 3.7 保存与删除

**正式/测试环境（上传门禁）**——点**保存**：数据先上传开发者平台，**上传成功才写入本地资产并自动封签**：

- 上传期间整个面板冻结（顶部显示"正在上传地块数据…"），SceneView 拖拽同步冻结；
- 成功：弹"保存成功（已封签）"，条目进入列表；
- 失败：弹"上传失败"及原因，**本地不落盘**，工作副本保留可修改后重试。

> 注意：后端当前为追加插入，同一 id 重复保存会在服务端累积多条记录（后端待做去重），编辑确认好再保存。

**离线环境**——点**保存**直接写入本地资产（不上传、无封签），弹"已本地保存"。

**删除**：仅删本地资产，不同步远端；删除后该环境组**自动重签**（正式/测试）；删除正在编辑的条目会自动退出编辑态。列表固定五行高、支持按 id 搜索，正在编辑的行蓝色高亮，新建草稿橙黄"未保存"行。

### 3.8 防篡改封签（为什么不能手改资产）

为保证**本地地块数据与平台上传数据一致**，正式/测试环境的地块组带防篡改签名：

- 编辑器每次保存/删除后自动对该组重算签名写入资产；
- 运行时加载时**验签**：失败（含签名被删）→ **整组拒用 + Error 日志**，区域对齐与地块显示均不生效——刻意 fail-loud，不静默降级；
- 所以任何改动都必须走地块编辑器（保存自动过上传门禁，天然与平台一致）；直接在文本编辑器/Inspector 里改资产 = 运行时整组失效；
- 签名失效的恢复：验证面板**"重新封签"**（§2.5），或在编辑器中逐条重新保存；
- 离线环境组无封签（本地直存语义，不参与一致性保证）。

## 4. 运行时匹配原理（速览）

- 运行时读地块资产的**激活环境标记**取对应环境组，并先**验签**（失败整组拒用，见 §3.8）；
- 中控下发区域长宽 → SDK 取**绝对值截断取整**（不四舍五入）拼成临时 id（`宽x长` 小写，如远端 len:6.2/width:4 → `4x6`）；
- 临时 id 与该组条目 id **精确比对**（大小写敏感）——所以条目 id 必须原样来自远端规格列表，不要手改；
- 匹配成功 → 按区域公式计算并驱动场景根节点（日志 `Region 计算完成[4x6]: …`）；
- 匹配失败 → 根节点保持原位，日志给出含长宽/临时 id/有效条目数的 Warning——排查先看这条。

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| 点"创建新条目"提示需要 SDK 验证 | 先完成当前环境的验证（§2）；注意每个环境单独验证 |
| 接口报 `[10006] AccessToken 已失效` | 令牌被重新生成过，用最新令牌重新验证 |
| 上传报 `[10007] 游戏不存在或无权限` | AppId 不属于当前令牌的开发者账号，核对该**环境**创建游戏时生成的这一对 appId/token |
| 菜单里找不到 MyVerse 入口 | SDK 版本需 ≥3.1.4；Package Manager 刷新包后重启编译 |
| 运行时日志"Region 快照无匹配地片" | 激活环境不对（数据在另一个环境组）/ 条目 id 与远端长宽生成的临时 id 对不上：确认面板切的环境、条目从规格列表创建、未手改 id |
| 运行时日志"…签名校验失败…整组拒用" | 资产被绕过编辑器修改，或迁移后未补签——验证面板"重新封签"或逐条重新保存 |
| 运行时日志"激活环境 […] 无地块条目" | 面板切换环境同步了激活标记，但该环境组还没配地块；或旧版数据在测试组而激活的是正式 |
| 运行时日志"本地区域数据列表加载失败" | 资产不在 `Resources/MVXRSDK/LocalRegionData` 契约路径 |

## 6. 从 3.1.x/3.2.x 升级（自动迁移）

升级到 3.3.0 后首次在编辑器打开面板/地块编辑器时自动完成迁移（幂等）：

1. **旧凭据 → 测试环境**：3.2.x 及之前的单环境凭据（当时默认连的就是测试环境地址）迁入测试环境并保留验证状态；**正式环境需重新验证**；
2. **旧地块 → 测试环境组**：旧平铺条目迁入测试环境组，**签名留空**——运行时会拒用，需在验证面板（测试环境）点**"重新封签"**补签；
3. 迁移后激活环境默认为**正式**——若要继续用测试环境的数据，在面板把环境切到测试。
